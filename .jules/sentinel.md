## 2024-05-15 - Command Injection via ping utility
**Vulnerability:** The `ping` command in `PingUtil.kt` accepts an unsanitized `host` parameter which is interpolated directly into a shell command `Runtime.getRuntime().exec(arrayOf("ping", "-c", count.toString(), "-W", timeoutSec.toString(), host))`. This allows command injection if the host contains spaces or shell metacharacters.
**Learning:** Runtime.getRuntime().exec() with arrayOf() protects against SOME command injection if arguments are properly separated, but it's still dangerous if the command itself interprets the arguments unexpectedly, or if the array elements contain shell metacharacters that slip through. **Prevention:** Avoid Runtime.exec if possible, use InetAddress.isReachable or ensure strict validation of the host parameter.
## 2024-05-15 - SSRF via UPnP SSDP response
**Vulnerability:** NetworkDiscovery.kt parses the `LOCATION` header from SSDP responses directly and performs an HTTP GET request to that URL in `fetchUpnpDescription` (`java.net.URL(url).openConnection()`). A malicious device on the LAN can broadcast an SSDP response with a LOCATION header pointing to internal or external sensitive endpoints (e.g. `http://localhost:8080/admin`, AWS metadata `http://169.254.169.254`, etc.), leading to a Server-Side Request Forgery (SSRF) and data exfiltration or internal service interaction.
**Learning:** Trusting URLs provided by unauthenticated network broadcasts without validation is a classic SSRF attack vector. In UPnP discovery, the LOCATION URL must be strictly validated to ensure its host matches the IP address from which the UDP packet originated, or at least restricted to the local subnet.
**Prevention:** Parse the URL and verify that the host matches the sender's IP address (`response.address.hostAddress`).
